## 오늘의 핵심

**Git은 파일을 저장하는 곳이 아니라 "상태의 변화"를 기록하는 곳이다.**
그래서 작업 영역이 셋으로 나뉜다 — 고치는 곳(Working Directory), 올릴 것을 고르는 곳(Staging Area),
확정하는 곳(Repository). `add` 가 따로 있는 이유는 **고친 것 전부가 아니라 일부만 커밋할 수 있게** 하기 위해서다.

```
Working Directory --add--> Staging Area --commit--> Local Repo --push--> Remote Repo
```

**커밋 메시지 접두사** — `feat` 기능 / `fix` 버그 / `doc` 문서 / `chore` 설정.
이 저장소의 커밋 규칙으로 정해 [루트 README](../README.md#️-기록-규칙) 에 적어뒀다.

## 짚어둔 것

- **원격 연결 순서** — `git init` 만으로는 `push` 가 안 된다.
  `git remote add origin <주소>` → `git branch -M main` → `git push -u origin main`.
  `-u` 를 한 번 붙여두면 다음부터는 `git push` 만 쳐도 된다.
- **마크다운은 엔터 한 번으로 줄이 안 바뀐다.** 같은 문단으로 합쳐진다.
  줄을 바꾸려면 문장 끝에 **공백 2칸**을 넣거나 빈 줄로 문단을 나눠야 한다.
