## 오늘의 핵심 3가지

**1. 시맨틱 태그는 디자인이 아니라 접근성 문제다.**
`<div>` 와 `<header>` 는 화면상 똑같이 그려진다. 다른 건 **기계가 읽을 때**다. 화면 낭독기와
검색엔진은 `<div>` 만 보고는 그게 메뉴인지 본문인지 알 수 없다. 그래서 시맨틱 태그를 써도
**배치가 저절로 되지는 않는다** — 의미는 HTML이, 배치는 CSS가 한다. 이 둘을 헷갈리면 안 된다.

**2. `box-sizing: border-box` 없이는 박스모델 계산이 어긋난다.**
기본값(`content-box`)이면 `width: 200px` 상자에 `padding: 20px` 을 준 순간 실제 너비가
**240px** 이 된다. 레이아웃이 밀리는 원인의 대부분이 이것이다.

**3. `position: static` 이면 `top` · `left` · `z-index` 가 전부 무시된다.**
→ **어제 AI 코딩 실습에서 모달이 안 보였던 원인이 정확히 이것이었다.**

## 직접 확인한 것

### 폼이 실제로 무엇을 보내는가

`method` 를 GET/POST로 바꿔가며 주소창과 전송값을 관찰했다. 표로 외운 게 아니라 눈으로 봤다.

- 한글이 `%EA%B9%80` 처럼 바뀐다 → **URL 인코딩**
- 체크박스 여러 개는 `avail_language=HTML&avail_language=CSS` 처럼 **같은 이름이 반복**된다
- **체크 안 한 라디오 · 체크박스는 아예 안 들어간다.** 빈 텍스트 칸은 `sex=` 로 들어가는데
  체크박스는 키 자체가 사라진다 — "빈 값"과 "없음"이 다르다

**값을 꺼내는 법이 입력 종류마다 다르다** — text·date·range는 `.value`, 체크박스 하나는
`.checked`, 체크박스 묶음은 반복문, multiple select는 `.selectedOptions`.

> 여기서 걸린 함정 하나. 같은 `name` 이 **하나뿐이면 목록이 아니라 요소 하나**가 온다.
> 이 예외 처리가 빠지면 체크박스를 하나로 줄였을 때 코드가 조용히 깨진다.

### 네이버에서 `<head>` 를 지워봤다

콘솔에 `document.head.parentNode.removeChild(document.head)` 를 치니 CSS가 통째로 사라졌다.
그런데 **일부 영역은 여전히 옷을 입고 있었다** — 그 부분이 `iframe` 으로 만들어져 있어서다.
페이지 하나가 실제로는 여러 문서의 조합이라는 걸 눈으로 확인했다.

### 강의 기준과 바깥 기준이 다른 것

강의에서 말한 "웹 3.0(CGI 등장)" 은 흔히 말하는 웹 3.0(시맨틱 웹 · 블록체인)과 **다른 구분**이다.
검색할 때 헷갈리지 않도록 기억해 둘 것.

## 실습

### ① AI에게 구조만 시켜보기 → 되묻기

CSS를 배우기 전이라 **구조만** 요청했다. 제약은 *CSS 금지 · 시맨틱 태그 우선 · 태그마다 선택 이유 주석*.

AI가 준 첫 결과는 대부분 `<div>` 였다. **"여기서 `<div>` 대신 시맨틱 태그를 쓸 수 있는 곳이 있어?"**
라고 되묻자 `<article>` `<dl>` `<footer>` 로 바뀌었다.

되묻는 과정에서 근거로 확인한 것 —

- `<button>` 의 `type` 을 생략하면 `form` 안에서 **submit으로 동작해 폼이 전송된다**
- `<dl>` 은 "이름-값" 쌍에 맞고 `<table>` 은 2차원 데이터용이다
- `<data value="1523000">1,523,000원</data>` — 사람이 읽는 값과 기계가 읽는 값을 같이 담는다

> **첫 답을 최종본으로 받지 않는 것**이 결과 품질을 갈랐다.

### ② 계좌 카드에 CSS 입히기

`06_account_card/` 폴더에 `index.html`(구조) 과 `style.css`(표현) 로 분리.
코드 안에 **박스모델은 `ⓐ~ⓔ`, Flexbox는 `①~③`** 으로 표시해 나중에 찾을 수 있게 했다.

만들면서 확인한 것 셋 —

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 카드 폭이 밀림 | `box-sizing` 기본값이 `content-box` | `border-box` 전역 적용 |
| 마지막 카드 아래 여백이 남음 | `margin-bottom` 은 마지막 요소에도 붙음 | flex의 `gap` — '사이'에만 생긴다 |
| 계좌번호가 은행명보다 안쪽으로 밀림 | `<dd>` 의 브라우저 기본 들여쓰기 **40px** | `margin-left: 0` |

버튼 두 개에는 `flex: 1` 을 줬다. 남는 공간을 반씩 나눠 가지므로 **글자 수가 달라져도 폭이 흔들리지 않는다.**

> Flexbox 속성은 [Flexbox Froggy](https://flexboxfroggy.com/) 로 손에 익혔다.
> `justify-content`(주축) 와 `align-items`(반대축) 가 갈린다는 걸 여기서 확실히 잡았다.

### ③ 나의 포트폴리오 페이지

`header` / `main` / `footer` 를 시맨틱 태그로 구성하고 `header` 에 두 페이지를 오가는 내비게이션 바.
제출이 **별도 remote repository** 단위라 처음부터 독립 저장소로 만들어 GitHub에 올렸다.

### 프론트엔드 프롬프팅에서 배운 것

"채팅 화면 만들어줘" 라고만 하면 AI가 임의의 프레임워크로 코드를 던진다. 그래서 셋을 먼저 적는다 —
**프레임워크 명시**("CDN 포함 단일 HTML 파일로"), **구조 묘사**("상단에 네비게이션 바, 중앙에 Card 형태 폼"),
**커스텀 CSS 최소화**. 안 적으면 나중에 수정이 불가능한 길이의 코드가 나온다.

## 회고

**Keep** — 태그마다 "왜 이걸 골랐는지" 주석을 한 줄씩 남긴 것. `button` 의 `type` 을 생략하면 폼이
전송된다는 건 주석을 쓰려고 근거를 찾다가 알게 됐다. 설명을 적으려면 먼저 이해해야 한다.

**Problem** — AI가 준 첫 구조는 대부분 `<div>` 였다. 그대로 받았으면 "동작은 하지만 의미가 없는"
HTML이 남았을 것이다. 되물었을 때야 시맨틱 태그로 바뀌었는데, **되물을 줄 몰랐으면 몰랐을 문제**다.

**Try** — 요청할 때 제약(프레임워크 · 단일 파일 · 커스텀 CSS 최소화)을 처음부터 적어 본다.
오늘은 결과를 받고 고치는 쪽이었는데, 제약을 먼저 주는 편이 왕복이 적을 것 같다.

> `position: static` 이면 `top` 과 `z-index` 가 무시된다는 것을 오늘 CSS 시간에 배웠는데,
> 어제 AI 코딩 실습에서 모달이 화면에 안 보였던 원인이 정확히 그것이었다.
> **어제는 증상으로 겪고 오늘은 규칙으로 배운 셈이다.** 규칙을 알고 나니 그때 왜 콘솔에
> 에러가 안 떴는지도 설명이 된다 — 문법이 틀린 게 아니라 조건이 안 맞아 무시된 것이었다.
