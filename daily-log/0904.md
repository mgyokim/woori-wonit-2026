## 오늘의 핵심 세 가지

**1. 에러가 났는데 엉뚱한 곳을 가리켰다.**

`Cannot read properties of null (reading 'edgesOut')` 만 보면 내 코드가 잘못된 것 같다.
실제 원인은 **Node 버전**이었는데 그런 말은 한 줄도 없었다.
지금까지는 *"에러가 안 나서"* 못 찾았다면, 오늘은 **에러가 났는데도 못 찾았다.**
메시지를 그대로 믿지 말고 **어느 단계에서 죽었는지**(`Installing dependencies with npm...`)를 봐야 했다.

**2. DOM 을 직접 만지는 건 오늘로 끝이다.**

`document.getElementById` 가 `main.jsx` 에 **딱 한 번** 나오고, 그 뒤로는 안 쓴다.

```jsx
createRoot(document.getElementById('root')).render(<App />)
```

Day 3~7 내내 `getElementById` 로 요소를 찾아 `innerText` 를 바꿨는데,
React 는 **데이터를 바꾸면 화면이 따라오는** 방식이다. 손잡이를 한 번만 넘겨주고 끝낸다.

**3. 컴포넌트는 함수 하나가 화면 한 조각이다.**

`<App />` 을 열 번 쓰니 계좌 카드가 열 번 그려졌다. 정의는 하나인데 태그처럼 여러 번 부른다.
다만 **열 개가 전부 똑같았다** — 데이터가 함수 안에 박혀 있어서다.
"재사용"이 되려면 **바깥에서 값을 넣어줄 수 있어야** 한다는 게 여기서 보였다.

## nvm 명령어 정리

버전을 바꿔가며 쓸 일이 생길 것 같아 함께 적어둔다.

```bash
nvm use 22            # 22 계열 최신으로 전환 (지금 이 터미널에만)
nvm use 22.23.2       # 정확한 버전 지정
nvm use --lts         # 최신 LTS 로
nvm use system        # nvm 이전에 깔려 있던 버전으로 되돌리기

nvm ls                # 깔린 버전 목록 (-> 화살표가 현재, default 별칭 표시)
nvm current           # 지금 버전만 확인
nvm ls-remote --lts   # 설치 가능한 LTS 목록

nvm alias default 22  # 새 터미널을 열어도 22 를 쓰게 (한 번만 하면 됨)
nvm uninstall 21      # 특정 버전 삭제
```

**`use` 와 `alias default` 가 다르다** — `use` 는 지금 이 터미널만, `alias default` 는 앞으로 열 터미널까지.
이걸 헷갈리면 "분명 바꿨는데 새 창에서는 옛날 버전"이 된다.

## 화면이 그려지기까지 — 파일 세 개

만들어진 구조에서 **실제로 화면을 만드는 건 세 파일**이다. 나머지는 설정이다.

```
index.html          ← 브라우저가 처음 받는 문서
  └ src/main.jsx    ← React 를 그 문서에 꽂는다
      └ src/App.jsx ← 실제 화면
```

### `index.html` — 왜 루트에 있나

```html
<div id="root"></div>
<script type="module" src="/src/main.jsx"></script>
```

**본문이 `<div id="root">` 하나뿐이다.** 나머지는 전부 JS 가 채운다.
`public/` 이 아니라 **프로젝트 루트**에 있는 이유는, Vite 가 이 파일을 **진입점으로 읽어서**
안에 걸린 `src/main.jsx` 를 따라 들어가기 때문이다. 정적 파일 취급이 아니라 시작점이다.

### `main.jsx` — 문서에 꽂는 자리

```jsx
createRoot(document.getElementById('root')).render(<App />)
```

**Day 3~7에 쓰던 `document.getElementById` 가 여기서 딱 한 번 나온다.**
이 한 줄로 React 가 `#root` 를 넘겨받고, 그다음부터는 내가 DOM 을 직접 만지지 않는다.

### `App.jsx` — 화면 한 조각

```jsx
function App() {
  const account = { bankName: '우리WON뱅킹', balance: 1523000, ... }

  return (
    <>
      <p className="header">- 상태: 정상</p>
      <p>-은행명: {account.bankName}</p>
      <p>-잔액: {account.balance}</p>
    </>
  )
}
export default App
```

**함수 하나가 화면 한 조각**이다. 위쪽에 필요한 데이터를 두고, `return` 에 그릴 것을 적는다.

## JSX 에서 걸린 것

### `class` 가 아니라 `className`

`class` 는 JavaScript 예약어라 못 쓴다. JSX 는 HTML 처럼 보이지만 **결국 JS** 다.

### `{}` 안에는 자바스크립트가 들어간다

```jsx
<p>-은행명: {account.bankName}</p>
<p>-잔액: {account.balance.toLocaleString()}원</p>
```

**따옴표 없이 값이 그대로 박힌다.** 템플릿 리터럴의 `${}` 와 비슷한데, JSX 에서는 `$` 없이 `{}` 다.

### 주석 자리가 두 종류다

`return()` **바깥**은 평범한 JS 라 `//` 를 쓰고, **JSX 안**에서는 `{/* */}` 로 감싸야 한다.
`{}` 안이 JS 표현식이라 그렇다.

### 여러 요소를 감싸는 `<>...</>`

`return` 은 **하나만** 돌려줄 수 있어서 `<p>` 를 여러 개 나란히 두면 에러가 난다.
의미 없는 `<div>` 로 감싸는 대신 **프래그먼트** `<></>` 를 쓰면 **DOM 에 아무것도 안 남는다.**

> Day 3에 *"의미 없는 `<div>` 를 줄이자"* 고 정리했는데, React 는 그걸 위한 문법을 따로 뒀다.

## 컴포넌트가 뭔지 확인한 방법

`main.jsx` 에서 `<App />` 을 **열 번** 썼다.

```jsx
<StrictMode>
  <App /> <App /> <App /> ... (10개)
</StrictMode>
```

같은 계좌 카드가 **열 번 그려졌다.** 함수 하나를 정의해두고 태그처럼 여러 번 부르는 것 —
이게 컴포넌트라는 걸 말로 듣는 것보다 이렇게 보는 게 빨랐다.

> 다만 지금은 **열 개가 전부 똑같다.** `account` 데이터가 `App` 안에 하드코딩돼 있어서다.
> 계좌마다 다른 값을 보여주려면 **바깥에서 값을 넘겨줘야** 하는데, 그게 다음에 배울 `props` 인 것 같다.

## 인라인 스타일도 해봤다 (주석으로 남겨둠)

스타일을 **객체로 만들어 `style={}` 에 넘기는** 방식을 먼저 짜봤다가, 지금은 주석 처리해뒀다.

```jsx
const styles = {
  card: { borderRadius: '16px', border: '1px solid var(--border)' },
}
<div style={styles.card}>
```

CSS 와 다른 점이 둘이다.
- 속성이 **camelCase** — `border-radius` 가 아니라 `borderRadius`
- 값이 **문자열** — `16px` 이 아니라 `'16px'`

**CSS 변수(`var(--border)`)는 그대로 쓸 수 있다.** `index.css` 의 `:root` 에 선언된 걸 가져다 쓴다.
