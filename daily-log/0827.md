## 1. Git 되돌리기

어제는 기록하는 법, 오늘은 되돌리는 법. **기록을 남기는 이유가 되돌아가기 위해서**라는 관점.

| 지금 상황 | 쓸 명령어 |
| --- | --- |
| 파일을 고쳤는데 되돌리고 싶다 (`add` 전) | `git restore <파일>` |
| `add` 했는데 빼고 싶다 | `git restore --staged <파일>` |
| 방금 커밋 메시지가 오타다 | `git commit --amend -m "..."` |
| 방금 커밋을 취소 | `git reset --soft HEAD~1` |
| 이미 `push` 한 커밋을 취소 | `git revert <해시>` |
| 날린 커밋을 되살리기 | `git reflog` → `git reset --hard <해시>` |

**reset 세 가지 — 어디까지 되돌릴 것인가**

| 옵션 | 저장소 | 스테이징 | 작업 폴더 |
| --- | --- | --- | --- |
| `--soft` | 되돌림 | 그대로 | 그대로 |
| `--mixed` (기본값) | 되돌림 | 되돌림 | 그대로 |
| `--hard` | 되돌림 | 되돌림 | 되돌림 ⚠️ |

오른쪽으로 갈수록 더 많이 지운다. 헷갈리면 `--soft` 부터가 안전하다.

**reset vs revert**

| | 하는 일 | 언제 |
| --- | --- | --- |
| `reset` | 기록을 지움 | 아직 push 안 한 내 작업 |
| `revert` | "취소"라는 기록을 더함 | 이미 push 한 것 |

> `reset` 은 장부를 찢는 것, `revert` 는 빨간 줄을 긋고 "취소"라고 적는 것.
> 공유된 기록에 `reset` 을 쓰면 남이 이미 받아간 히스토리와 어긋난다.

**기억할 세 가지**

- `git reflog` 는 Git의 블랙박스다. `git log` 는 지금 남은 기록만, `reflog` 는 날린 것까지 전부 보여준다.
  → **한 번이라도 커밋한 건 사실상 안 사라진다.** (뒤집으면, 지우고 싶은 파일도 안 사라진다는 뜻)
- 반대로 **커밋 안 한 변경은 `restore` 하면 진짜 사라진다.** "자주 커밋하라"는 말의 진짜 이유.
- **Fork** 는 clone과 달리 GitHub 서버 안에 내 저장소를 새로 만드는 것. 원본에 쓰기 권한이 없을 때 쓴다.

## 2. AI 코딩 도구

| 단계 | 하는 일 | 사람이 하는 일 |
| --- | --- | --- |
| 자동완성 | 다음에 올 코드를 회색으로 제안 | `Tab` 을 누를지 말지 판단 |
| 채팅 | 질문에 답하고 코드를 제안 | 무엇을 물을지 정하기 |
| 에이전트 | 여러 파일을 직접 고치고 명령도 실행 | 어디까지 맡길지 정하기 |

### AI는 코드를 어떻게 만드는가

**다음에 올 말을 확률로 고른다.** 코드도 글자라서, `function add(a, b) {` 다음엔 `return a + b;` 가 올
확률이 높고 AI는 그걸 고른다. **맞는지 틀리는지를 판단하는 게 아니다.**

> 그래서 AI는 "그럴듯한" 코드를 만든다. "맞는" 코드가 아니라. 자신 있게 틀리고, 미안해하지도 않는다.

여기서 한계가 전부 파생된다.

| 한계 | 코딩에서는 |
| --- | --- |
| 환각 | 없는 함수 · 라이브러리를 만들어낸다 (`array.removeDuplicates()` — JS에 없음) |
| 지식 단절 | 예전 문법, 이미 안 쓰는 방식을 추천한다 |
| 맥락 이탈 | 내 프로젝트를 모른다. **내가 보여준 파일만** 안다 |

### 지킬 세 가지

| 원칙 | 코딩에서는 | 왜 |
| --- | --- | --- |
| 다 넣지 않는다 | API 키 · 비밀번호 · 실제 고객 정보 · 회사 코드를 붙여넣지 않는다 | 채팅창에 넣는 순간 내 손을 떠난다 |
| 사람이 본다 | AI가 준 코드는 실행해보기 전까지 모른다 | 그럴듯한 것과 맞는 건 다르다 |
| 남긴다 | 왜 이 코드를 골랐는지 주석과 커밋에 | 3일 뒤의 나는 오늘의 나를 기억 못 한다 |

## 3. Copilot 사용법

| 방법 | 단축키 | 언제 |
| --- | --- | --- |
| 자동완성 | `Tab` 수락 · `Esc` 거절 | 짧고 반복되는 코드 |
| **인라인 채팅** | `Ctrl + I` | **코드를 선택해두고** 그 자리에서 고칠 때 |
| 채팅 패널 | `Ctrl + Alt + I` | 여러 번 주고받을 때 |

- **슬래시 명령** : `/explain` `/fix` `/tests` `/doc`, 그리고 답이 계속 이상하면 `/clear` 부터.
- **문맥 붙이기** : `#selection` (선택 영역) · `@terminal` (터미널 에러) · `@vscode` (VS Code 기능).
  파일 전체가 필요하면 채팅창에 드래그.
- **모드** : `Ask` 분석·질의응답 / `Agent` 파일 수정·명령 실행까지 자율 수행 / `Plan` 구현 계획만 먼저 작성.

> 가장 많이 쓰는 흐름은 **코드 선택 → `Ctrl + I` → 질문**. 선택한 코드를 AI가 자동으로 보기 때문에 복붙이 필요 없다.

## 4. 프롬프트 엔지니어링

### 4요소

| 요소 | 업무에서는 | 개발에서는 |
| --- | --- | --- |
| **역할** | "너는 금융 감사 담당자야" | "너는 비전공자를 가르치는 JavaScript 튜터야" |
| **근거** | 사규 문서 첨부 | 코드를 선택해서 준다 (`Ctrl + I`) |
| **형식** | "표로 정리해줘" | "고친 코드 말고 설명부터 3줄로" |
| **모를 때** | "없는 건 없다고 해" | "확실하지 않으면 어디를 확인해야 하는지 알려줘" |

> **코딩에서만 추가되는 다섯 번째 — 실행 환경.**
> "순수 HTML/CSS/JS로만, 라이브러리 쓰지 말고"를 안 적으면 AI는 React나 jQuery를 쓴다고 가정하고 답한다.

### 정확도를 올리는 6가지

| | 방법 | BEFORE → AFTER |
| :---: | --- | --- |
| ① | **명시적으로 쓴다** | "정리해줘" → "장애 원인을 3줄로. 원인 → 영향 → 조치 순서로 문장형으로" |
| ② | **왜 그런지 말한다** | "불릿 쓰지 마" → "보고서에 붙여 넣을 거라 문장형이 필요합니다" |
| ③ | **예시를 2~3개 준다** | 말로 어려운 기준은 예시가 대신한다 (1개면 그 형식만 따라 하고, 5개 넘으면 분량만 먹는다) |
| ④ | **구획을 나눈다** | 지시와 데이터를 `<규칙>` `<데이터>` 로 분리 → **프롬프트 인젝션** 방지 |
| ⑤ | **생각할 시간을 준다** | "원인 후보 3가지를 나열하고, 근거를 확인한 뒤, 최종 하나를 제시하세요" |
| ⑥ | **출력 계약을 맺는다** | 뒤에 시스템이 붙으면 형식은 협상 대상이 아니다 (JSON 스키마 고정) |

**나쁜 예 / 좋은 예**

```
❌ 이 코드 설명해줘

⭕ 선택한 코드가 무슨 일을 하는지 비전공자가 알아듣게 설명해줘.
   - 한 줄씩 말고, 전체 흐름을 3~4문장으로 먼저
   - 어려운 용어가 나오면 괄호 안에 쉬운 말로
   - 마지막에 "이 코드를 한 문장으로" 요약
```

## 6. 실습 ② 낯선 코드 읽기

> [`01_코드읽기`](https://github.com/mgyokim/woori-wonit-ai-coding/tree/main/01_%EC%BD%94%EB%93%9C%EC%9D%BD%EA%B8%B0) — 동작은 정상이지만 함수명이 `f1`~`f4`, 변수명이 `a`·`tmp`·`arr2` 인 코드

실무에서 첫 달에 하는 일은 새 코드를 쓰는 게 아니라 **남이 쓴 코드를 읽는 일**이라는 전제로 시작한 실습.

| 하고 싶은 것 | 슬래시 | 반드시 덧붙일 말 |
| --- | --- | --- |
| 설명받기 | `/explain` | "비전공자가 알아듣게" |
| 이름 바꾸기 | (그냥 요청) | **"동작은 바꾸지 말고 이름만"** |
| 주석 달기 | `/doc` | "한글로, 줄마다 말고 함수 위에만" |
| 테스트 만들기 | `/tests` | "경계값과 실패 케이스도 포함해줘" |

- **"동작은 바꾸지 말고"** 를 안 적으면 AI가 로직까지 고쳐놔서, 어디서부터 잘못됐는지 찾을 수 없게 된다.
- `f3` 설명을 받은 뒤 콘솔에서 `console.log(f3(TRANSACTIONS))` 로 **직접 실행해 확인**했다.
  AI 설명은 문장이 매끄러울수록 더 믿음이 가는데, 그게 함정이다.
- 주석은 코드를 그대로 옮긴 것(`i를 1 증가시킨다`)이 아니라 **"왜 이렇게 했는지"** 가 들어가야 한다.
- 테스트는 **경계값**이 핵심 — 0, 음수, 아주 큰 수.
- "이름만 바꿔줘"에 파일을 통째로 다시 쓰면 **"바뀌는 부분만 보여줘"** 를 붙인다.

## 7. 실습 ③ AI로 디버깅하기

> [`02_버그잡기`](https://github.com/mgyokim/woori-wonit-ai-coding/tree/main/02_%EB%B2%84%EA%B7%B8%EC%9E%A1%EA%B8%B0) — 버그 5개가 심어진 계좌 화면. 상세 분석은 해당 폴더 README

### 디버깅 3종 세트

**"안 돼요"는 프롬프트가 아니다.** 사람한테도 그렇게 물으면 도와줄 수 없다.

```
[재현 조건] 입금 버튼을 눌렀을 때
[기대 동작] 잔액이 1만원 올라가야 합니다
[실제 동작] 아무 반응이 없습니다. 콘솔 에러는 없습니다.

먼저 수정사항을 설명하고 변경해야 할 코드를 출력하세요.
```

- **에러는 통째로** 붙인다. 첫 줄만 복사하면 `at ...` 줄에 있는 파일명·줄번호가 빠져서 AI가 추측할 수밖에 없다.
- **"먼저 설명해줘"가 핵심.** 고친 코드만 받으면 붙여넣고 끝나지만, 설명을 먼저 받으면 **AI가 틀렸을 때 눈치챌 수 있다.**

| 유형 | 제일 먼저 할 일 | AI에게 줄 것 |
| --- | --- | --- |
| 콘솔에 빨간 에러 | 에러의 파일명 · 줄번호로 가기 | 에러 전문 + 그 줄 주변 코드 |
| 에러 없음, 동작 안 함 | `console.log` 로 실행이 도달하는지 확인 | 3종 세트 + 관련 코드와 HTML |
| 숫자가 이상함 | 입력값과 출력값을 적어두기 | 넣은 값 / 기대한 값 / 나온 값 |
| 화면이 이상함 (CSS) | 개발자도구로 요소가 있긴 한지 확인 | 보이는 모습을 말로 + 관련 CSS |

> **CSS는 에러가 나지 않는다.** 브라우저는 이해 못 하는 CSS를 조용히 무시한다.
> 그래서 "뭐가 잘못됐다"가 아니라 **"지금 이렇게 보이는데 이렇게 보이고 싶다"** 로 묻는다.

### 잡은 버그 5개

| # | 증상 | 원인 | 콘솔 에러 |
| :---: | --- | --- | :---: |
| 1 | 로드 즉시 알럿, 버튼은 무반응 | `addEventListener("click", handleDeposit())` — 괄호 때문에 즉시 실행되고 `undefined` 가 등록됨 | 없음 |
| 2 | 환율에 `[object Promise]` | `async` 함수 반환값을 `await` 없이 문자열과 결합 | 없음 |
| 3 | 잔액이 `-`, 입금해도 안 바뀜 | `getElementById("blance")` 오타 → `null` + 데이터만 바꾸고 화면 재렌더 누락 | **있음** |
| 4 | 이자에 `26652.500000000004` | 원 단위 반올림 없음 + 부동소수점 오차 + `formatCurrency()` 미사용 | 없음 |
| 5 | 이체 확인 모달이 안 보임 | `.modal-overlay` 에 `position` 누락 → `top`/`left`/`z-index` 가 전부 무시됨 | 없음 |

원인 규명에서 갈렸던 두 개.

- **4번은 원인이 세 겹**이었다. `.5` 는 계산이 맞아서 나온 값이고(이자는 원래 소수가 나온다),
  `000000000004` 는 2진 부동소수점 오차다. **서로 다른 두 문제가 한 줄에 같이 보이던 상황.**
  `Math.round()` 로 원 단위 반올림하면 둘이 한 번에 해결된다. AI는 여기서 `toFixed(2)` 를 권하는데,
  **문자열이 되고 소수점도 남아서 틀렸다.** 금액은 원 단위 정수로 다뤄야 한다.
- **5번은 문법 오류가 아니라 유효한 CSS**라서 콘솔에 아무것도 안 뜬다. `classList.remove("hidden")` 도
  실제로 잘 실행돼서 Elements 탭엔 "열려 있는" 것으로 보인다. `position` 이 없으면 기본값이 `static` 이고,
  `static` 요소에서는 `top`/`left`/`z-index` 가 **전부 무시**된다. 개발자도구 **Computed 탭**에서
  `top` 에 취소선이 그어진 걸 보고서야 잡혔다.

수정 후 Node 내장 러너로 11개 케이스를 검증했다. (`node --test 02_버그잡기/app.test.js`)
다만 5번은 가짜 DOM이 레이아웃을 계산하지 않아 **테스트로 못 잡는다** — 브라우저에서 눈으로 봐야 한다.

> **콘솔에 에러가 뜬 건 다섯 중 하나뿐이었다.** 나머지는 "에러는 없는데 결과가 이상한" 유형이라
> 에러 메시지가 아니라 **기대 동작과 실제 동작의 차이**에서 출발해야 찾을 수 있다.
> 3종 세트를 챙기라는 이유가 이것이다.

## 회고

**Keep** — 버그를 잡을 때마다 원인을 한 문장으로 적고 넘어간 것. 5개 중 4개가 콘솔 에러가 없는
유형이라, 기록이 없었으면 다음에 같은 걸 또 헤맸다.

**Problem** — `f3` 설명을 AI에게 받았을 때 문장이 매끄러워서 그대로 믿을 뻔했다. 콘솔에서 직접
실행해보고서야 확인이 됐다. 검증이 아직 습관이 아니라 의식적으로 해야 하는 단계다.

**Try** — AI 답변을 붙여넣기 전에 "왜 이 코드인지" 한 문장을 커밋 메시지나 주석에 남긴다.
설명하지 못하면 그건 고친 게 아니라 붙여넣은 것이다.

> AI가 코드를 써준다면 사람이 하는 일은 **무엇을 물을지 정하고, 답이 맞는지 판단하는 일**이다.
> 이자 버그에서 AI는 문법적으로 멀쩡한 `toFixed(2)` 를 답으로 준다. 틀렸다고 알아보는 건 사람이다.
