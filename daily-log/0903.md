## 오늘의 핵심 세 가지

**1. `getter` / `setter` 는 함수인데 변수처럼 쓴다.**

```js
아이유.deposit = 40000   // 함수 호출이다. 대입처럼 생겼을 뿐
아이유.checkAmount       // 이것도 함수 호출. 괄호가 없다
```

**함수인 걸 숨겨서 값처럼 다루게 하는 문법**이다. 그래서 쓰는 쪽 코드가 단순해진다.
그런데 `getter` 만 있는 속성에 대입하면 **에러도 안 나고 그냥 무시된다.**
`아이유.checkAmount = -9999999999999999` 을 해도 잔액은 그대로였다.

**2. `#private` 는 진짜로 안 보인다.**

```js
console.log(아이유)              // { name, accountNumber, cusAccountNo } — #balance 가 없다
console.log(Object.keys(아이유))  // 여기에도 없다
```

**없는 게 아니라 숨어 있다.** 클래스 안에서는 읽고 쓰는데 바깥에서는 접근이 막힌다.
그래서 `getter` 로만 확인하고 `setter` 로만 바꾸게 된다 —
*"변수에 직접 접근할 수 있다는 건 직접 망가뜨릴 수도 있다는 뜻"* 이라는 설명이 이걸로 이해됐다.

**3. 타자 게임 버그 8개 중 콘솔에 잡히는 건 0개였다.**

스페이스바를 누르면 초기화 버튼이 다시 눌리고, Ctrl·Tab 을 눌러도 점수가 깎이고,
점수는 음수로 무한히 내려갔다. **전부 직접 눌러봐야 보이는 것들**이었다.

> **이제 다섯 번째다.** Day 2 버그 4개 · Day 4 `default` 없는 `switch` · Day 5 `0 < age` ·
> Day 6 `let i` 와 JSON 손실, 그리고 오늘 8개.
> "콘솔이 조용하면 정상"이라는 감각은 이제 확실히 틀렸다.

## 클래스 — 은행 계좌를 만들어봤다

`BankAccount` 라는 클래스를 만들고 `InsAccount` 로 상속까지 해봤다.
[Day 5](./0901.md) 에서 *"고객의 자산은 은행의 부채"* 를 들은 뒤라 계좌를 소재로 잡으니 감이 왔다.

### 세 종류의 것이 클래스 안에 산다

| | 붙는 곳 | 키워드 | 예 |
| --- | --- | --- | --- |
| **클래스 변수** | 클래스 자체 | `static` | `bankName`, `accountNo`(총 계좌수) |
| **클래스 메서드** | 클래스 자체 | `static` | `hello()` |
| **인스턴스 변수** | 만들어진 객체마다 | `this` | `name`, `accountNumber`, `#balance` |
| **인스턴스 메서드** | 만들어진 객체마다 | — | `deposit`, `withdraw`, `checkAmount` |

**`static` 은 인스턴스를 안 만들고도 부른다.** `BankAccount.hello()` 처럼.
반대로 인스턴스 메서드는 `아이유.checkAmount` 처럼 만들어진 객체를 통해야 한다.

계좌를 만들 때마다 `++BankAccount.accountNo` 로 **클래스 변수를 올려서 총 계좌수를 센다.**
개별 계좌가 아니라 은행 전체가 가져야 할 값이라 `static` 이 맞는 자리다.

### 상속 — `extends` 와 오버라이딩

```js
class InsAccount extends BankAccount {
  static bankName = '동양'   // 변수 오버라이딩
  static accountNo = 0       // 계좌수도 따로 센다

  constructor (name, accountNumber, balance, kind = '변액') {  // 생성자 오버라이딩
    super(name, accountNumber, balance)   // 부모 생성자를 먼저 부른다
    this.kind = kind                      // 그 다음 내 것을 추가
  }
}
```

**`hello()` 를 물려받았는데 결과가 다르다.**

```
BankAccount.hello()  →  어서오세요. 우리은행입니다~ ... 1개의 계좌
InsAccount.hello()   →  어서오세요. 동양은행입니다~ ... 3개의 계좌
```

메서드는 하나인데 **`this` 가 누구냐에 따라 다른 값을 읽는다.**
`InsAccount.hello()` 로 부르면 `this` 가 `InsAccount` 라서 오버라이딩한 `bankName` 을 쓴다.
"코드를 재사용한다"가 **복사가 아니라 이런 뜻**이었다.

`super()` 를 먼저 부르지 않으면 `this` 를 쓸 수 없다. 부모가 만든 뒤에야 내 것을 얹을 수 있다.

## DOM 과 이벤트 — 화면을 코드로 바꾼다

### 카운터 (`exam2.html`)

`+` `-` `초기화` 버튼으로 숫자를 바꾸는 실습. 간단해 보였는데 걸린 게 셋이었다.

**① 주석에 적어둔 요구사항을 코드에 안 넣었다**

```js
// 값이 0이 되면 더이상 숫자가 줄어들 수 없음   ← 이렇게 적어놓고
function minus() {
  document.getElementById("num").innerText--;   ← 가드가 없다
}
```

**-1, -2 로 계속 내려갔다.** [Day 5](./0901.md) 의 `0 < age` 와 **똑같은 유형**이다.
주석은 맞는데 코드가 안 따라갔다. 이번엔 이틀 만에 또 나왔다.

**② `innerText++` 가 되는 게 오히려 함정이다**

`innerText` 는 문자열인데 `++` 가 동작한다. JS가 숫자로 바꿔 더하고 다시 문자열로 넣기 때문이다.
동작은 하지만 **화면이 곧 상태**라서, 값을 읽고 쓰는 자리가 세 군데로 흩어져 있었다.
`getCount()` / `setCount()` 로 묶으니 한 곳만 고치면 되게 됐다.

**③ `reset` 이라는 함수 이름**

지금은 되지만 버튼이 `<form>` 안에 들어가면 **폼의 `reset()` 이 먼저 잡혀서 내 함수가 안 불린다.**
`resetCount` 로 바꿨다. 전역에 흔한 이름을 쓰면 언젠가 가려진다.

### 이벤트를 HTML 에 적을 것인가, JS 에 적을 것인가

```html
<button onclick="startGame()">시작</button>          <!-- HTML 에 동작이 섞인다 -->
```
```js
startBtn.addEventListener('click', startGame)        // JS 가 동작을 맡는다
```

둘 다 되지만 **뒤엣것이 낫다는 걸 오늘 몸으로 확인했다** (아래 타자 게임에서).

## 타자 게임 — 문제를 찾아 고치고 배포까지

주어진 코드에서 **문제점을 찾아 고치고, 파일을 분리해 GitHub Pages 에 올리는** 과제.

### 찾은 문제 8개

| | 문제 | 어떻게 고쳤나 |
| --- | --- | --- |
| 1 | **스페이스바를 누르면 초기화된다** | 버튼 클릭 후 포커스가 남아 스페이스·엔터로 재활성화. `preventDefault()` + `blur()` |
| 2 | Ctrl · Tab · 방향키에도 점수가 깎인다 | 제외 목록을 늘리는 대신 `event.key.length !== 1` 한 줄로 |
| 3 | 점수가 음수로 무한히 내려간다 | `Math.max(0, ...)` |
| 4 | 같은 문자가 연달아 나온다 | 직전 문자를 제외하고 뽑기 |
| 5 | 키보드 없는 기기에서 못 한다 | 숨은 `input` 에 포커스를 줘서 모바일 키보드 호출 |
| 6 | 잘했는지 알 수 없다 | 정확도 · 최고 점수(`localStorage`) 추가 |
| 7 | `#score` 에 `cursor: pointer` | 클릭 핸들러가 없는데 클릭 가능해 보였다. 제거 |
| 8 | 동작이 HTML 안에 섞여 있다 | `onclick` → `addEventListener` |

**1번이 제일 오래 걸렸다.** 게임 중 스페이스를 치면 갑자기 리셋되는데 왜인지 몰랐다.
버튼을 클릭하면 **포커스가 그 버튼에 남고**, 포커스된 버튼은 스페이스·엔터로 다시 눌린다는 걸
알고 나서야 풀렸다. 콘솔에는 아무것도 안 찍힌다.

**2번은 접근이 바뀐 케이스다.** 처음엔 `excludedKeys` 배열에 `Control`, `Alt`, `Tab`, `ArrowUp` ...
을 계속 추가하려고 했다. 그러다 **문자 키는 `event.key` 가 한 글자**고
`Shift` · `Control` · `F1` 은 두 글자 이상이라는 걸 알았다. 목록 대신 성질로 거르니 한 줄이 됐다.

### 파일을 나누니 생긴 이득

`index.html`(구조) · `style.css`(표현) · `script.js`(동작) 로 나눴다.

그 뒤에 **디자인을 통째로 다른 스타일로 바꿔봤는데 `script.js` 를 한 줄도 안 고쳤다.**
HTML 의 `id` 와 클래스 이름만 유지했더니 구조와 표현만 갈아끼워졌다.
[Day 3](./0828.md) 에서 *"의미는 HTML, 배치는 CSS"* 라고 적었던 게 **실제 이득으로 돌아왔다.**

> 바꿔본 디자인은 결국 **원래 것이 더 나아서 되돌렸다.**
> 이미 올린 커밋이라 `reset` 대신 **`git revert`** 를 썼다 —
> 되돌리는 새 커밋을 쌓는 방식이라 원격 히스토리를 지우지 않는다.
> [Day 2](./0827.md) 에 정리한 Git 되돌리기가 여기서 쓰였다.

### 배포

새 저장소를 만들고 **GitHub Pages** 로 올렸다. `Settings → Pages → Deploy from a branch → main / (root)`.

- `index.html` 이 루트에 있으면 **파일명 없이** 접속된다. 다른 이름이면 경로에 파일명까지 적어야 한다
- **경로 대소문자를 서버는 구분한다.** 맥은 구분을 안 해서 로컬에서 되던 게 Pages 에서만 404 날 수 있다

## 회고

**Keep** — 문제를 목록으로 안 늘리고 **성질을 찾은 것.** 특수키를 하나씩 배열에 넣다가
"문자 키는 한 글자"라는 걸 알아채고 한 줄로 끝냈다. 목록은 계속 새는데 규칙은 안 샌다.

**Problem** — **카운터에서 또 주석과 코드가 어긋났다.** "0 밑으로 안 내려간다"고 적어놓고
가드를 안 넣었다. Day 5에 같은 걸 겪고 회고까지 썼는데 이틀 만에 반복했다.
적는 걸로는 안 고쳐진다.

**Try** — 주석에 조건을 쓰면 **그 자리에서 바로 그 조건을 코드로 옮긴다.** 나중에 채우지 않는다.
